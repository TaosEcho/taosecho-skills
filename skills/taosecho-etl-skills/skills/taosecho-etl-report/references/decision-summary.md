# 决策摘要强约束

决策摘要是报告的第 1 页。无论 brief、standard、full 模式，第 1 页必须严格按本约束生成。

## 必含 5 块（顺序固定）

### 1. 基本信息

固定字段（每个必填）：
- 产品名（来自 state.md product.title）
- 产品 ID（来自 state.md product.id）
- 平台（来自 state.md product.platform）
- 分析日期（state.md source.fetched_at）
- 分析档位（state.md analysis_tier 或推断）
- 证据等级（state.md evidence.level）

### 2. 阶段判断

固定 3 选 1：继续推进 / 先补关键证据 / 暂缓投入

来自 dev-decision 的输出。如果 dev-decision 未跑，标“阶段判断未完成，先跑 dev-decision”。

附总分 X/12。

### 3. 六维评分表

固定 6 行：需求 / 场景 / 顾虑 / 竞品 / 风险 / 页面承接
固定 3 列：维度名 / 分数（0-2） / 状态（清楚 / 待补 / 偏弱 / 缺失）

未跑过 dev-decision 时该块整体省略，由“接下来做什么”指引用户先跑 dev-decision。

### 4. 接下来做什么（3 条具体动作）

每条必须包含：
- 动作描述（具体可执行）
- 解决什么问题（绑定证据：Review N 条 / Q&A N 条等）
- 预期效果（通过后能达到什么）

动作类型按阶段判断差异：
- 继续推进 -> 动作 = 推进 + 风险防范 + 加速建议
- 先补关键证据 -> 动作 = 补什么 + 怎么补 + 补完预期评分变化
- 暂缓投入 -> 动作 = 暂缓理由 + 重启条件 + 替代方向

### 5. 不能忽视的风险（3 条）

每条必须带数据点：低星 Review N 条 / Q&A N 条 / 证据来源。

如果 risk-check 未跑，此块标“风险分析未完成”。

### 6. 可选：关键证据缺口

仅在阶段判断为“先补关键证据”或“暂缓投入”时出现。
列出 evidence.gaps 中的关键项。

## 禁止项

- 禁止“建议”“也许”“可能”“应该”等模糊词作为决策结论。
- 禁止没数据点的判断。
- 禁止超出上述 5-6 块之外的内容。
- 禁止表情符号。
- 禁止 markdown 装饰线。
- 禁止把 6 维评分表当装饰，分数必须来自 dev-decision 算法。

## 决策摘要长度

不超过 1 页 A4：约 600 字 + 1 张评分表 + 2 张列表。

## 不同模式下的决策摘要

- brief：决策摘要 = 整份报告主体的 70%。
- standard：决策摘要 = 报告第 1 页，后续 7-11 页是详细分析。
- full：决策摘要 = 报告第 1 页，后续 14-24 页是详细分析 + 证据缺口附录。
